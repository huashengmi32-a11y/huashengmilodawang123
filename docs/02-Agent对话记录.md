## 轮次 4：Agent 自主实施过程

用户确认方案后，Agent 连续完成下列工作；此处按时间顺序记录关键动作与结论，便于复核实现过程。

### 4.1 数据源结构探查

| 步骤 | 动作 | 结论 |
| --- | --- | --- |
| 1 | 请求 600519 页面并打印所有 table 的 id | 分红表 `sharebonus_1`（9 列）、配股表 `sharebonus_2`（11 列） |
| 2 | 打印分红表全部行 | 表头占 2 行：公告日期 / 分红方案(每10股) / 进度 / 除权除息日 / 股权登记日 / 红股上市日 / 查看 |
| 3 | 追踪「查看」链接 | 明细页 `vISSUE_ShareBonusDetail.php?stockid=..&type=1&end_date=..`，含 29 行键值对 |
| 4 | 比较候选股票数据量 | 600519 31 条、000001 38 条（含 3 条配股）、601398 23 条（含 1 条配股） |

### 4.2 抓取

- 编写 `scripts/fetch_sina.py`：会话复用、0.6s 限速、3 次退避重试、本地缓存、抓取清单。
- 首次运行抓取 95 个页面；补充配股明细后再次运行，仅新增 4 次网络请求，其余 95 个页面命中缓存，
  验证了缓存机制（最终共 99 个页面：3 个列表页 + 96 个明细页）。

### 4.3 解析与清洗

- 首次运行解析结果为 0 条记录：字段清单漏掉列表末尾的「查看」列，导致行数校验全部跳过 → **修复**：
  在字段清单末尾补 `__detail__` 占位。
- 修复后得到 92 条分红记录、4 条配股记录；质量规则命中 8 条。
- 复核命中项发现 8 条均为平安银行 2005–2012 年的「不分配」方案 → **优化**：R2 规则区分
  「不分配」与「空方案」，前者降级为提示并保留记录，保证年度序列完整。
- 修正明细页标题与 CSV 表头中遗留的英文字段名（`implement_year` → 「实施年度」）。
- 将 `stocks.json` / `issues.json` 的键统一为英文，CSV 仍使用中文表头，便于程序消费与人工查看。

### 4.4 UI 设计（ui-ux-pro-max skill）

- 第一次调用 `--design-system` 得到「Enterprise Gateway」营销首页版式 → 与实际产品（数据报告页）不匹配。

  字体（Fira Sans / Fira Code）、密度（8/10）与动效（3/10）适用，营销版式部分予以覆盖并记录在
  `design-system/sina-dividend-lab/pages/report-page.md`。
