> 本文档是 Plan 模式确认需求阶段的留痕，用于说明「需求 → 方案 → 确认 → 验收标准」的闭环。

## 一、作业要求

| 项目 | 内容 |
| --- | --- |
| 题目 | 第三章 新浪财经历史分红数据获取与预处理（基于 Codex） |
| 交付要求 | ① 使用 Git 并提交仓库链接；② 开发网页展示实现过程与结果并提供截图；③ 提交与 Agent 交互的全部对话（脱敏） |
| 考核点 | ① Plan 模式确认需求；② 使用 ui-ux-pro-max skill 设计 UI；③ 使用 Playwright 做网页测试 |

## 二、需求澄清

提交作业要求后，Agent 先提出方案并由使用者确认，关键约定如下。

| 待确认事项 | 确认结果 |
| --- | --- |
| 数据源 | 新浪财经个股「分红送转」页 `vISSUE_ShareBonus` + 「分红明细」页 `vISSUE_ShareBonusDetail` |
| 目标股票 | 600519 贵州茅台、000001 平安银行、601398 工商银行（覆盖白酒与银行两类，且含配股记录） |

| 输出格式 | CSV（中文表头，UTF-8 BOM）+ JSON + 质量报告 |
| 网页形态 | 单页静态站点，无需服务器、可离线打开，展示实现过程与结果 |

| Git 仓库 | 由使用者提供远端仓库地址，Agent 完成本地提交与推送 |

> 使用者在确认方案后提供了远端仓库地址，视为对上述方案的确认。

## 三、方案要点

1. **抓取层**：`requests.Session` + 本地缓存 + 限速 + 退避重试，原始 HTML 全量留档。
2. **解析层**：BeautifulSoup 按表头列位解析三张表，避免硬编码下标。
3. **清洗层**：占位符归一为缺失值、日期归一 ISO、数值去噪、派生分析字段。
4. **校验层**：七条规则逐条检查，问题逐条留痕到 `data/issues.csv`。
5. **导出层**：CSV / JSON / 质量报告 / 网页数据包。
6. **展示层**：ui-ux-pro-max 生成设计系统，落地为静态报告页。
7. **测试层**：Playwright 覆盖渲染、交互、分页、排序、筛选、键盘可达与响应式布局。

## 四、验收标准

- [ ] 三个脚本按 `fetch → preprocess → build_site` 顺序执行，可从零复现全部数据产物。
- [ ] `data/` 下产出分红、配股、股票汇总、问题日志与质量报告。
- [ ] `site/index.html` 直接双击可打开，且关键指标、明细表、图表、质量报告均正确渲染。
- [ ] Playwright 用例在桌面与移动视口全部通过，并产出交付截图。
- [ ] Git 仓库包含完整提交记录，远端链接可访问。

## 五、风险与边界

| 风险 | 处理方式 |
| --- | --- |
| 页面结构变更导致解析失败 | 表格缺失时写入 R1 问题记录并报错退出，不产出「空成功」结果 |
| 高频抓取给对方站点造成压力 | 请求间隔 0.6s、失败退避重试、命中缓存不重复请求 |
| 明细页占位符比例高 | 统一按缺失值处理并在质量报告中给出字段覆盖率 |
| 分红年度口径存在歧义 | 标注为「推断字段」，并在 README 与质量报告中说明推断规则 |
